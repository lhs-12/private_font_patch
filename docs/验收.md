<h1><center>字体宽度验收</center></h1>

先跑一次 `bash scripts/patch-fonts.sh`, 让系统字体带上补丁. 字体用默认的 `Iosevka Term`, 不需要额外的字体配置.  
下面每个表格里竖线的位置都是 `oxfmt` 认为的宽度, 所以字体渲染出的宽度对得上, 竖线就会对齐.

本文件要通过 oxfmt 验证.

# 7. 已知残余(不齐是正常的)

完整的残余清单和分类见 `README.md` 的 "还剩什么". 这里放最典型的几类.

## 7.1 缺字形: 全机没有字体能给它们 1 格(184 个)

| 字符 | 名称 | oxfmt 期望 | 实际会占 |
| ---- | ---- | ---------- | -------- |
| ☁    | 云   | 1 格       | 2 格     |
| ☂    | 伞   | 1 格       | 2 格     |
| ☎    | 电话 | 1 格       | 2 格     |
| ♨    | 温泉 | 1 格       | 2 格     |
| ♻    | 回收 | 1 格       | 2 格     |
| ✂    | 剪刀 | 1 格       | 2 格     |
| ✈    | 飞机 | 1 格       | 2 格     |
| ✉    | 信封 | 1 格       | 2 格     |
| ☠    | 骷髅 | 1 格       | 2 格     |
| ⛰    | 山   | 1 格       | 2 格     |
| 🏔    | 雪山 | 1 格       | 2 格     |

它们是 "文字默认呈现" 的 emoji (`Emoji_Presentation=No`), `oxfmt` 按 1 格算, 但 `Iosevka` 没有它们的字形, 只能落到后面的字体, 结果都是 2 格.  
全机所有字体面里没有一个能给它们 1 格, 所以不补字形就修不掉. 表格和对齐场景里别写它们, 改用有字形的写法(如 `❄️` `⚠️`), 或直接写 "云" "剪刀" 这样的文字.  
在 kitty 这类终端里它们还会直接不显示(原因见 `README.md`), 要显示就写成带 U+FE0F 的 `☁️` `✂️`.

## 7.2 Iosevka 自己把它们画宽了(23 个)

| 字符        | 名称       | oxfmt 期望 | 实际会占 |
| ----------- | ---------- | ---------- | -------- |
| ⟝ ⟞ ⟵ ⟶     | 长箭头     | 1 格       | 2 格     |
| ⟷ ⟸ ⟹ ⟺     | 长箭头     | 1 格       | 2 格     |
| ⟻ ⟼ ⟽ ⟾ ⟿ ⬳ | 其余长箭头 | 1 格       | 2 格     |

这一类的字形是有的, 只是 Iosevka 给它们的 advance 就是 `1em`(2 格).  
完整的 23 个是 `U+27DD-U+27DE`, `U+27F5-U+27FF`, `U+2B33`, `U+1F8D0-U+1F8D8`(后两组在本机字体里画不出来, 不必细看). 要修得改 Iosevka 的 `hmtx`, 当前不做.

## 7.3 Nerd Font 图标

`Iosevka Term` 没有的那些 Nerd Font 图标(PUA, 如 `U+F121`)由 `Symbols Nerd Font Mono` 提供, 而它的字形一律是 `1em` = 2 格, `oxfmt` 却算 1 格, 所以写进表格会偏. 别在表格里用 Nerd Font 图标.

# 8. 一行字符加一把尺子: 豆腐 / 颜色 / 宽度

```
|123456789012345678901234567890123456789012345678901234567890123456789012|
|A a 1 中 あ 한 ✅ ❌ ⭐ ⚠ ⚠︎ ⚠️ ❄ ❄️ ❤ ❤️ ✔ ✔️ ↑ ↓ → ← ★ ● 🎉 😀 🚀 🇨🇳 1️⃣|
```

两行一起看:

- 第 2 行有没有 □ 空框(豆腐);
- ⚠️ 是彩色, ⚠︎ 是黑白(变体选择符);
- 两行右端的 `|` 是否在同一列(宽度).

整行宽度是逐字符之和, 所以有一个字符不符, 右边那根 `|` 就会偏.  
要确认这个测试有分辨力: 在行尾加上 `☁` `✂` `✈`, 应该右偏 3 格.

终端里这套不成立. 终端按自己的 `wcwidth` 摆格子, `|` 不会移, 要看的是字形有没有留缝或压到邻居.

# 9. markdowntable 补丁的验收

本文件整体已经过 `oxfmt` 排版, 所以在打开的 `docs/验收.md` 上跑一次 `Markdown Table: Format all tables.`:

- **什么都不变** -> 表格格式化走的是 `oxfmt`, 补丁生效.
- 除第 1 节外所有表格都被重排(列宽变了) -> 走的是插件自己的宽度表, 补丁没生效.

下面这张表是两种算法分歧最大的字符, 插件会把 `⚠️` 算成 4 格、`👨‍👩‍👧` 算成 11 格, 而 `⌚` 只算 1 格:

| 字  | 插件算 | oxfmt 算 | 为什么                           |
| --- | ------ | -------- | -------------------------------- |
| ⚠️  | 4      | 2        | `FE0F` 被插件当成 2 格           |
| 🎉  | 3      | 2        | 插件把 `U+1F300-1F1FBFF` 记 3 格 |
| ⌚  | 1      | 2        | 插件的全角范围只从 `U+2600` 起   |
| ⏰  | 1      | 2        | 同上                             |
| 👨‍👩‍👧  | 11     | 2        | 逐码点相加, 不认 ZWJ 连字        |
| 🇨🇳  | 4      | 2        | 两个区域指示符各算 2 格          |
| 1️⃣  | 4      | 2        | 数字 + `FE0F` + 键帽             |
